# 零食商城后台管理系统 - 开发指南

## 📦 技术栈
- Vue 3 + Composition API
- Vue Router 4
- Pinia (状态管理)
- Element Plus (UI组件库)
- Axios (HTTP请求)
- Vite (构建工具)
- ECharts (数据可视化)

## 🚀 快速开始

### 1. 安装依赖
```bash
cd 后台管理系统
npm install
```

### 2. 配置环境变量
创建 `.env.development` 文件：
```env
VITE_API_BASE_URL=http://localhost:3000/api
```

### 3. 启动开发服务器
```bash
npm run dev
```

访问 `http://localhost:5173`

### 4. 登录账号
- 账号: admin
- 密码: admin123

## 🔧 核心功能

### 1. 数据看板 (Dashboard)
- 订单统计（今日/本周/本月）
- 商品统计
- 用户统计
- 销售趋势图表（ECharts）

### 2. 商品管理
- **商品列表**: 查询、新增、编辑、删除、上下架
- **商品分类**: 分类管理、排序

### 3. 订单管理
- **订单列表**: 查询、筛选、状态管理
- **订单详情**: 查看订单详情、发货、取消
- **订单统计**: 各状态订单数量统计

### 4. 用户管理
- **用户列表**: 查看用户信息、禁用/启用
- **用户详情**: 查看用户订单、积分、优惠券

### 5. 营销管理
- **优惠券管理**: 创建、编辑、删除优惠券
- **轮播图管理**: 上传、排序、删除轮播图

### 6. 系统设置
- **管理员管理**: 添加、编辑、删除管理员
- **系统配置**: 商城名称、联系方式等

## 🔐 权限说明

后台使用 JWT Token 认证，需要在请求头中携带：
```
Authorization: Bearer {token}
```

登录成功后，Token 会自动存储到 localStorage，axios 拦截器会自动添加到请求头。

## 🔨 开发规范

### 1. 命名规范
- 组件名: PascalCase (如 ProductList)
- 文件名: PascalCase (如 ProductList.vue)
- 函数名: camelCase (如 getProductList)
- 常量名: UPPER_CASE (如 API_BASE_URL)

### 2. 代码风格
- 使用 Composition API
- 使用 `<script setup>` 语法
- 使用 ref/reactive 管理状态
- 使用 async/await 处理异步

### 3. 提交规范
```
feat: 新功能
fix: 修复bug
docs: 文档更新
style: 代码格式调整
refactor: 重构
perf: 性能优化
test: 测试
chore: 构建/工具变动
```

## 📦 构建部署

### 构建生产版本
```bash
npm run build
```

构建产物在 `dist/` 目录

### 预览构建结果
```bash
npm run preview
```

### 部署
将 `dist/` 目录部署到静态服务器（Nginx、CDN等）

### Nginx 配置示例
```nginx
server {
    listen 80;
    server_name admin.your-domain.com;
    
    root /path/to/dist;
    index index.html;
    
    location / {
        try_files $uri $uri/ /index.html;
    }
    
    location /api {
        proxy_pass http://localhost:3000/api;
    }
}
```

## ⚠️ 注意事项

1. **开发环境**：确保后端API服务运行在 http://localhost:3000
2. **跨域问题**：开发环境由 Vite 代理解决，生产环境需要 Nginx 配置
3. **图片上传**：需要配置图片上传接口和存储服务
4. **权限控制**：根据实际需求实现更细粒度的权限控制

## 🐛 常见问题

### 1. 登录失败
- 检查后端服务是否启动
- 检查数据库是否有管理员数据
- 检查 API 地址配置是否正确

### 2. 图片无法显示
- 检查图片 URL 是否正确
- 检查静态资源服务是否配置

### 3. 接口请求失败
- 检查网络连接
- 检查后端 API 是否正常
- 查看浏览器控制台错误信息
